> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

### Task 3: M2 `session-alerts` 純函式

**Files:**
- Create: `src/session-alerts.ts`
- Create: `src/session-alerts.test.ts`

**Types（建議）:**

```ts
export type AlertKind = "waiting" | "advice";

export interface AlertEvent {
  sessionId: string;
  kind: AlertKind;
  at: string; // ISO 或可比較字串
  edgeKey: string;
}

export interface JumpTarget {
  sessionId: string;
  kind: AlertKind; // waiting → main；advice → advice view
}
```

**Produces:**
- `alertEdgeKey(sessionId, kind, atOrAdviceId): string`
- `collectAlertEvents(input): AlertEvent[]`  
  - input 含：各 session 的 activity／updatedAt、`unreadAdviceCounts` 或最新 advice `at`、`selectedSessionId`  
  - **排除** `selectedSessionId`  
  - waiting：`isWaitingForUser(activity)`  
  - advice：該 session 有「未讀」新 advice（App 傳入 per-session 最新未確認 edge，例如最新 advice 的 `at+kind`）
- `sortAlertEvents(events): AlertEvent[]` — waiting 全部在前，再依 `at` 新→舊
- `formatAlertBanner(events, shortId): string | undefined`
- `nextJumpTarget(events): JumpTarget | undefined` — 排序後第一則
- `shouldRingAlertBell(prevEdge: string | undefined, nextEdge: string | undefined): boolean`（沿用 waiting bell 精神）

- [ ] **Step 1: Write failing tests**（至少涵蓋）
  - 排除目前 session
  - waiting 優先於 advice
  - `nextJumpTarget` kind 正確
  - banner：多個 waiting／單一 advice
  - 同 edge 不重複響（`shouldRingAlertBell`）
- [ ] **Step 2: FAIL → Implement → PASS**

**Banner 文案（寫死範例，可微調但測死）：**
- 僅 waiting、n=1：`⚠ {shortId} 正在等你 · 按 n 跳轉`
- 僅 waiting、n>1：`⚠ {n} 個 session 在等你 · 按 n 跳轉`
- 無 waiting、有 advice、n=1：`用量建議 · {shortId} · 按 n 查看`
- 無 waiting、advice>1：`有 {n} 則跨 session 用量建議 · 按 n 查看`
- waiting 與 advice 同時：只顯示 waiting 文案（優先序）
